# Hooklane v0.1.1

## 概要

Webhookの受付と配送を分離し、retry、dead-letter、pending recovery、status参照を扱うHooklaneについて、公開文書、repository metadata、事実の整合を整理した。ビルド済みimageやbinaryは配布しない。

## READMEと文書構成の整理

- READMEをWebhook配送基盤の概要、構成、障害時の動作、検証範囲から始まる構成へ変更
- 詳細な制約をLIMITATIONSへ、運用手順をOPERATIONSへ、実証済みの事実をRELEASE_EVIDENCEへ集約
- source-only配布、MIT License、third-party noticesへの導線を整理

## 古いCI・公開状態の記載修正

- GitHub hosted Actionsの実行済み状態と、quality / security / chart gates、kind delivery and recovery E2Eの成功を反映
- v0.1.1 tagをcurrent source baselineとして記載し、GitHub Releaseの有無をsource contractから主張しない
- cloud production、実在する外部downstream、長期負荷、本番traffic、30日SLO達成実績は未確認として維持

## Goal Loop開発文書の分離

- Goal Loopのrunner commandとsafety contractを[開発と検証方法](../DEVELOPMENT.md)へ移動
- READMEでは開発工程をproduct機能より前に出さず、文書への導線だけを残した

## package / repository metadata

- package descriptionとHelm chart descriptionをWebhook配送基盤として中立的な表現へ変更
- repository descriptionとtopicsを公開mainのHosted CI成功後に整備する

## application behavior

tag時点のapplication behaviorを記録するrelease noteであり、後続branchのruntime configuration変更は含めない。

## 検証結果

- docs contract、repository hygiene、lint、typecheck、unit／integration test、security scan、Helm／Kubernetes contractを実行
- clean-roomでtracked candidateから主要runtime検証とcleanupを再現
- GitHub hosted Actionsでquality / security / chart gatesとkind delivery and recovery E2Eを確認

## 既知の制約

- 配送はat-least-onceで、downstream側のevent IDによる重複排除が必要
- cloud production、外部downstream、multi-node／multi-zone、long-running load、production Alertmanager、on-call運用は未確認
- prebuilt container image、container registry、release artifact、binary distributionは含まない
